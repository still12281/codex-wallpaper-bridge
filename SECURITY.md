# Security and trust boundary

This experimental integration requires local debugging access to the desktop client. A CDP endpoint can expose more than wallpaper controls, including access to the renderer; use it only on a trusted local machine. Never bind it to `0.0.0.0`, forward it, or publish its browser/profile data.

The startup path verifies the installed official package and the ownership/identity of the loopback endpoint. The host targets the Codex shell, not arbitrary web pages. UI actions carry a per-connection token; search imports use server-issued path tokens and re-check canonical paths. These are defensive checks, not a sandbox against a malicious local administrator or another process with debugging access.

No installer changes the official package, signature, ACL, global execution policy, or content security policy. The default launcher does not force-close an ordinary running client. Optional restart/wait switches require deliberate use; prefer saving drafts and exiting the client yourself.

By default, the data directory (`%LOCALAPPDATA%\CodexWallpaperBridge`) is inside the current user's profile and is writable only by that user, `Administrators`, and `SYSTEM`. On multi-user computers, keep the default `%LOCALAPPDATA%` directory rather than placing the data directory (which also holds `CodexEntry.exe`, `launch-script.txt`, and versioned scripts) on a shared non-system drive such as `D:\` or `E:\`, because non-system drives on Windows typically inherit Modify permissions for `Authenticated Users`. If a custom non-system drive path must be used on a shared machine, restrict write access on that directory to the current user and administrators.

Only trusted local media and projects should be imported. Media decoding, FFmpeg and scene-package parsers may have bugs; keep dependencies updated. Compatible local images and MP4 videos may be played directly from their registered external paths in `settings.library` instead of copying bytes into `media/`; oversized or incompatible media continues to be transcoded into managed copies under `media/`. Both playback and preview paths restrict local media access to managed `media/` files and local external paths explicitly registered in `settings.library`, refuse UNC/network paths, `..` traversal, symbolic links/directory junctions along the path, and non-media extensions, and re-verify canonical `realpath`, file size, and timestamps (`mtime`/`ctime`) around loading. Lightweight video-layer mode keeps `<video>` muted and does not execute scene scripts. Optional WebGL Scene mode executes project scripts in an opaque `sandbox="allow-scripts"` iframe with a project-restricted resource broker. Native full-scene/web mode executes the project through the separately installed Wallpaper Engine, outside that iframe sandbox. Application wallpapers are not launched. Both live project routes retain the explicit confirmation step.

The optional Chromium Web source executes author code in an opaque iframe in an owned headless Chrome/Edge process. Codex receives JPEG frames only. A token-scoped loopback service restricts paths and resolved links to the project; the debugging transport is an inherited pipe, with no network debugger. Owned-page CSP and page/OOPIF request interception restrict resource loading; worker HTTP loading and WebRTC are unsupported. Entry pages containing author meta CSP are refused rather than rewriting that policy. This is a limited local-project route, not a complete audit of hostile Chromium content or every network API. See [implementation and validation limits](docs/BROWSER-WEB-20261027.zh-CN.md).

The highest scene tier prefers the native route after confirmation. Only the uniquely named, project-owned source window is captured; the desktop and chat are not capture sources. Per-window properties can be copied from the matching desktop project's saved settings, but desktop selections and global quality settings are not modified. This route still has capture/encoding/display costs and does not forward mouse interaction.

Library backups contain private settings, local paths and owned media. Store them outside the source repository and do not upload them as diagnostics. The maintenance tool restores into a separate empty directory, checks asset hashes, rejects UNC paths, and preserves external project and external media references without copying or deleting those external files. Imported backups should still be treated as trusted local configuration.

To report a vulnerability after publication, use repository private vulnerability reporting if the maintainer enables it. Do not disclose account data or exploitable private details in a public issue. There is no maintainer email in this unpublished candidate.
