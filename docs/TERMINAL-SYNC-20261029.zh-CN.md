# 终端主题漏同步修复（2026-10-29）

## 原因与漏检

用户截图中的原生终端是白色背景，而聊天区已使用深色壁纸主题。当前 Codex 26.1023.6621.0 加载 `app-initial-db76c3384587.js`；旧适配只接受两个固定模块文件名和对应压缩导出名，实际状态为 `unsupported`，终端保持官方浅色主题。同步设置 `surfaceSync.code` 本身是开启的。

此前只确认旧模块的 manager 可导入，当时实例数为 0；没有把用户实际打开的终端作为验收对象，却沿用了 `adapted` 状态。这是检查缺口，不是用户设置错误。壁纸播放 ready 也不能说明终端主题已经接上。

## 修正

- 在当前页面已加载的原生 `app-initial` 模块中检查唯一的终端 manager 接口，不再依赖具体 hash 或压缩导出名；要求直接数据字段为 Map，创建/释放方法为数据方法。候选有歧义、访问器字段或接口不符时保留原生行为，不调用未知导出。
- 保留原有 xterm 公开 options 适配与原色恢复，只修改主题；不读取 PTY、终端 buffer、命令或输出。沿用现有 DOM 观察，在相关模块/终端节点出现时尝试接入，没有新增轮询或外部监控。
- 空实例明确为 `armed`，存在已接入实例才为 `adapted`；关闭最后一个实例立即更新计数。模块尚未加载时可以在后续加载后恢复，不把同一接口失败反复重试。
- 宿主每次挂载按模块修改时间加载自有适配；现有健康回读增加 `terminalTheme`，使播放状态与终端状态能够分别检查。

## 当前客户端验证

先在运行页面热更新，再只替换桥接自有 Node 宿主以加载持久代码；官方 Codex 浏览器身份、主进程启动身份、13 条库及配置文件原始字节保持。原终端由 Codex 自身管理，没有关闭或重建其会话。

真实路径为：热更新时没有终端，状态 `armed/0`；用户随后在当前聊天打开终端，创建钩子接上，状态变为 `adapted/1`。回读到连接中的 xterm、55 行、透明终端底色、容器 `rgba(7,7,7,0.58)`、实际行文字颜色 `rgb(233,239,245)`，不再是白底黑字。自有宿主重新接入后仍为 `adapted/1`，背景 ready，无宿主错误。验证读取公开主题与计算样式，没有采集聊天/终端文本或截图。

无终端模块的分离页面保持 `unsupported/0`，不将其误记为已验证终端。没有为验收切换官方明暗主题或执行终端命令。
