# D：播放口径、GPU 高刷与有界缓存

本阶段源码已完成，并与E联合部署v18。主/分离窗口ready，配置字节一致，34个运行模块哈希一致。下面明确标为隔离的FPS/画质结果仍不能当成当前Codex实际可见/物理呈现验收；当前用户选择保留为原媒体，没有强制改为GPU或4K。

- 面板/运行状态分别显示设置上限、GPU renderer 提交 FPS、视频解码增量或原版 canvas 更新增量、输出与视口尺寸、原素材帧率（无旧元数据时明确未知）、实际画质和视频纹理精度。复用原有五秒状态周期，无新常驻采样器。暂停归零，静态档不再显示动态帧率。
- GPU 可选 120/144；媒体和原版保持最高 60。只改 FPS 时热更新，失败恢复旧值；恢复 setter 失败则重挂旧配置。高刷偏好不污染媒体导入默认，面板显示独立的新素材规格；切原版时使用该模式的已保存/媒体默认 FPS，并在原有确认中显示。
- 发现 4K 画布原先仍落在上游 renderDpr=1 的 R=.8 场景纹理预算。现通过固定一半 CSS 视口、renderDpr=2，保持实际 3840×2160，同时使用上游 R=1 高清资源预算。不是放大视频或补帧；普通档位不变。
- 资源缓存总量仍 512 MiB、单项 256 MiB；条目从 4 调至 128，防止几个小资源淘汰大型场景。仍无闲置 GPU 渲染器保活。按资源版本失效、路径围栏与候选采用保持。
- 增加按目标首帧就绪及全部目标完成耗时记录；健康当前项继续复用。原版传输未重写：当前没有新的瓶颈证据要求替换 JPEG/CDP。
