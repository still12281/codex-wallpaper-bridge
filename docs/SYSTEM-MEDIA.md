# Optional system media on Windows

Prepare `oneincase/media-bridge` v0.1.5 with `npm run prepare:media`, using the same `CODEX_WALLPAPER_DATA_DIR` as the host. Preparation requires authenticated `gh`; the Windows executable is downloaded separately, SHA-256 checked, and stored with its original MIT license outside Git. Release commit: `a508378f4e5e654c8de60e1076d559dca258e825`.

Both metadata and system output audio capture are off by default. Enable them independently in **系统音乐联动**. **显示歌曲信息与播放控制** controls metadata; **启用壁纸音频响应（WebGL 场景）** controls spectrum capture and scene audio processing. Audio-only mode clears song metadata sent to the scene. The shared helper may still read provider metadata internally. The helper uses protocol 1 over local standard input/output and a one-second metadata/status poll. Playback buttons require the active media provider's capabilities and an applied result. This adapter does not save continuous audio, forward album artwork or lyrics to scenes, or expose a general media API to wallpaper scripts.

Spectrum tiers are 10, 20, 30 and 60 updates per second (`systemMedia.audioFps`, default 30). Analysis, subscriptions and host delivery all follow the tier. Changing only the tier restarts the owned capture helper without reloading the scene. Higher tiers increase capture/IPC work; they are upper bounds, not measured visual FPS or a guarantee of native parity. Old settings preserve their existing enable flags and migrate to 30. The helper and delivery status report requested and active rates separately.

Turning audio response off remounts the WebGL candidate with explicit `audio:null`, which disables shader/script spectrum rather than falling back to the engine's simulated source. Failed candidate loads retain the previous background and roll the preference back. Ordinary videos cannot gain independent audio bars through this switch. Native-engine realtime audio remains controlled in Wallpaper Engine.

**仅聚焦 Codex 时播放动态壁纸** exposes the existing `pauseOnBlur` preference: clearing it allows visible unfocused windows to keep rendering and requesting spectrum. It does not override hidden/minimized pages or system reduced-motion preferences. The current user's existing focus preference is retained.

On Windows the helper is launched with `--no-online` to disable online lyrics lookup. Spectrum capture additionally requires at least one visible, ready, unpaused WebGL scene supporting audio processing; otherwise any remaining metadata helper uses `--no-audio`, even when the saved spectrum preference is enabled. If metadata is also disabled, the helper stops entirely. Foreground changes have a 600ms capture debounce. The old helper stops before its replacement starts. `--no-online` is a lyrics-provider option, not a universal firewall. The inspected Windows metadata adapter does not supply remote artwork URLs. Metadata/artwork caches may exist in the private runtime data directory. The official client and media player retain their own network behavior.

Frequency delivery stops immediately on a renderer pause and clears the previous spectrum once. Only newly received frames are forwarded, including valid silent frames. Media properties are sent when their content changes, with a separate position correction at most every five seconds while the scene is active. The scene reuses one media source. Closed music settings receive no DOM updates; reopening them receives current properties. Scenes without audio processing still receive media properties. Runtime status includes aggregate `mediaPower` counters and the owned helper PID for checking this policy without logging track names.

Scene imports declaring `general.supportsaudioprocessing=true` now use full native realtime in automatic mode, with the existing confirmation step. “仅视频层” remains an explicit reduced-effects choice: extracting a background video cannot retain independent audio shaders, text or scripts. WebGL remains a separate project-dependent choice. Both inspection and import use this decision before checking for an existing video copy.

On 2026-10-25 a local workshop scene's original circular audio-bar shader was verified in the actual Codex renderer. A hidden candidate first passed silent/nonzero spectrum comparisons. The applied WebGL scene then received real WASAPI frames through the normal mediaPower path: 43 spectrum deliveries at the sampled checkpoint, 12 nonzero renderer observations, maximum band value 157, with canvas readbacks showing the original ring. The saved blur-pause setting was restored after the bounded test. This accepts that scene's audio path, not full visual parity or arbitrary scenes. Font/local-asset warnings remain; total renderer/GPU cost was not benchmarked. The bridge process settled around 57 MiB working set after scene loading, excluding Codex renderer and GPU memory.

Actual source state and a received spectrum frame newer than one second are required before external audio is attached to WebGL. A provider exit, error or stale spectrum detaches live audio and installs a zero source instead of simulated frequency data. Scene BGM may still be processed while response is enabled; it is not evidence of live system audio. Explicitly turning response off disables all scene frequency processing through the mount option. The WebGL scene volume control does not alter system volume or native capture audio.

Local native evidence on 2026-10-24: metadata-only mode initialized successfully with audio idle; audio mode reported WASAPI running at 48kHz/stereo and delivered 22 spectrum events in about 2.5 seconds. The sampled output was silent (zero RMS/peak). This verifies the protocol and capture lifecycle, not a nonzero music-reactive visual effect. Isolated browser tests separately verify external spectrum attach/detach. Real player playback controls were not automatically pressed during acceptance.

## Follow-up native acceptance

The installed Codex sandbox rendered an original audio-text Scene using actual WASAPI spectrum: 27 received frames, sampled peak band 96/255, rendered text changed from `SYSTEM AUDIO 0` to `SYSTEM AUDIO 788`, then returned to zero after zero input. Pixel changes and rendered keys were both checked. A separate low-volume native WinRT fixture verified OS Next/Previous and Play/Pause with independent session/MediaPlayer readback. These tests establish audio delivery and engine response; arbitrary Workshop shader/script parity remains project-dependent.

The complete current-player control chain is **not fully accepted**. A real UI pause test changed playback, but Windows then promoted another application to current session. The prebuilt helper follows `GetCurrentSession` and cannot pin a player application. The original music session was restored by an exact-session development helper; that helper is not distributed. The host now displays the player identity, checks it before sending commands, prefers explicit play/pause capabilities, and requires actual state/track changes before reporting success. A native mismatched-identity test showed a visible error and preserved playback. This guard does not provide an atomic pinned-session API; multiple active players remain an explicit control limitation. No additional real queue-changing commands were sent after the source-switch failure.

## User-reported performance and parity limits, 2026-10-25

The user subsequently reported stutter and weak, mismatched audio response. The earlier ring readback accepts only signal delivery, not satisfactory responsiveness or desktop parity. Live diagnostics recorded automatic downgrades after 6 FPS and 19 FPS intervals. The desktop engine was configured at 30 FPS; this scene had been capped at 24 FPS. A bounded comparison kept the original effect chain and reduced its render-target budget through the renderer's low post-processing quality. Only this local scene entry now uses that budget and a 30 FPS cap; other scene defaults remain unchanged.

The helper analysis, subscription and host delivery now run at approximately 30 Hz instead of a 20 Hz analysis feeding 10 Hz subscriptions and 10 Hz delivery. The applied-scene follow-up test sampled 29.95–30.15 FPS (median 30.13) during a ten-second run and recorded 128 deliveries at its status checkpoint, compared with 43 in the earlier bounded run. These checkpoints are not synchronized latency measurements or a long-duration performance benchmark.

The pinned media-bridge v0.1.5 source mixes device audio to mono, resamples to 16 kHz, uses a 1024-sample FFT and quadratic frequency buckets with a -70..0 dB byte mapping. WebGL receives that same spectrum for both channels and applies its own calibration. Increasing update rate does not restore lost stereo information or reproduce Wallpaper Engine's native frequency/amplitude/smoothing semantics. Exact desktop parity is still unaccepted; the native-engine capture alternative has not been benchmarked for this scene. Pure video playback bypasses this scene renderer, but other wallpapers have not been individually accepted for fluidity.

Native option acceptance: 38 unit tests and the isolated WebGL lifecycle check passed. A backend-only Codex check verified the actual labels/rate choices, unfocused visible playback, and engine audio processing disabled with zero level after turning response off. In one short run, requested 10/20/30/60 Hz produced approximately 8.8/16.0/21.6/31.1 renderer updates per second; these are local load-dependent observations, not guarantees or CPU/GPU percentage measurements. Rate-only changes kept the renderer identity. The original focus, metadata and audio enable preferences and 30 Hz rate were restored.
