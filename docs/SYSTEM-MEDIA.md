# Optional system media on Windows

Prepare `oneincase/media-bridge` v0.1.5 with `npm run prepare:media`, using the same `CODEX_WALLPAPER_DATA_DIR` as the host. Preparation requires authenticated `gh`; the Windows executable is downloaded separately, SHA-256 checked, and stored with its original MIT license outside Git. Release commit: `a508378f4e5e654c8de60e1076d559dca258e825`.

Both metadata and system output audio capture are off by default. Enable them separately in **系统音乐联动**. The helper uses protocol 1 over local standard input/output, a one-second metadata/status poll, and optional 100ms spectrum subscriptions. Playback buttons require the active media provider's capabilities and an applied result. This adapter does not save continuous audio, forward album artwork or lyrics to scenes, or expose a general media API to wallpaper scripts.

On Windows the helper is launched with `--no-online` to disable online lyrics lookup. Spectrum capture additionally requires at least one visible, ready, unpaused WebGL scene supporting audio processing; otherwise the helper uses `--no-audio`, even when the saved spectrum preference is enabled. Foreground changes have a 600ms capture debounce. The old helper stops before its replacement starts. `--no-online` is a lyrics-provider option, not a universal firewall. The inspected Windows metadata adapter does not supply remote artwork URLs. Metadata/artwork caches may exist in the private runtime data directory. The official client and media player retain their own network behavior.

Frequency delivery stops immediately on a renderer pause and clears the previous spectrum once. Only newly received frames are forwarded, including valid silent frames. Media properties are sent when their content changes, with a separate position correction at most every five seconds while the scene is active. The scene reuses one media source. Closed music settings receive no DOM updates; reopening them receives current properties. Scenes without audio processing still receive media properties. Runtime status includes aggregate `mediaPower` counters and the owned helper PID for checking this policy without logging track names.

Actual source state and a received spectrum frame newer than one second are required before external audio is attached to WebGL. A provider exit, error, disabled capture or stale spectrum detaches it. WebWallGL then resumes its engine default audio processing, which can include simulation and scene BGM; that behavior is not evidence of live system audio. The WebGL scene volume control does not alter system volume or native capture audio.

Local native evidence on 2026-10-24: metadata-only mode initialized successfully with audio idle; audio mode reported WASAPI running at 48kHz/stereo and delivered 22 spectrum events in about 2.5 seconds. The sampled output was silent (zero RMS/peak). This verifies the protocol and capture lifecycle, not a nonzero music-reactive visual effect. Isolated browser tests separately verify external spectrum attach/detach. Real player playback controls were not automatically pressed during acceptance.

## Follow-up native acceptance

The installed Codex sandbox rendered an original audio-text Scene using actual WASAPI spectrum: 27 received frames, sampled peak band 96/255, rendered text changed from `SYSTEM AUDIO 0` to `SYSTEM AUDIO 788`, then returned to zero after zero input. Pixel changes and rendered keys were both checked. A separate low-volume native WinRT fixture verified OS Next/Previous and Play/Pause with independent session/MediaPlayer readback. These tests establish audio delivery and engine response; arbitrary Workshop shader/script parity remains project-dependent.

The complete current-player control chain is **not fully accepted**. A real UI pause test changed playback, but Windows then promoted another application to current session. The prebuilt helper follows `GetCurrentSession` and cannot pin a player application. The original music session was restored by an exact-session development helper; that helper is not distributed. The host now displays the player identity, checks it before sending commands, prefers explicit play/pause capabilities, and requires actual state/track changes before reporting success. A native mismatched-identity test showed a visible error and preserved playback. This guard does not provide an atomic pinned-session API; multiple active players remain an explicit control limitation. No additional real queue-changing commands were sent after the source-switch failure.
