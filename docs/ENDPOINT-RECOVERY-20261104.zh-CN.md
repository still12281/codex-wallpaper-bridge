# 端口恢复与启动句柄隔离

## 已完成的改动

- 入口优先复用经过身份检查的健康连接；默认端口占用时从 9335–9354 选择空闲 loopback 端口。
- 端点记录原子保存，每次复用重新核对唯一监听者、当前会话、官方主程序路径、创建时间与 CDP 浏览器身份。
- 任务栏和更新恢复使用实际端口；启动前重新检查端口和主实例，保留稳定入口互斥。
- 一体入口、自检、更新辅助程序、壁纸宿主和已登记 Store 程序的直接启动使用原生句柄隔离：无重定向时不继承句柄，重定向时仅传递标准流。
- 从调试客户端代开长期运行的应用，可使用 `windows/Start-ExternalApp.ps1 -FilePath <绝对可执行文件路径>`。该工具启动应用后退出，保留原有桌面入口、应用文件和设置。
- 句柄隔离在进程启动阶段完成，不新增常驻进程、监控或轮询。

## 实机结果

一次性正常退出重开后，入口使用 9336，主窗口和分离窗口壁纸均 ready，设置文件字节保持一致；保存端点和宿主复用成功。

旧 9335 的监听对象由另一个长期运行的应用及其语言服务共同持有。正常退出持有者后，LISTEN 消失且独占绑定成功；从原有桌面入口重新打开该应用后，没有再次持有 Codex 调试端口。

## 已通过的检查

Windows socket 夹具复现了父进程退出后子进程保留监听的行为。采用句柄隔离后，子进程继续运行，原端口立即可重新绑定。标准流重定向、Windows 参数引号、工作目录、环境、短命子进程退出码及启动/更新保护回归均通过。

私人设置、应用状态、原始日志和诊断产物保留在仓库外。
