# 默认端口残留与安全恢复

## 原因

本机出现 `127.0.0.1:9335` 仍为 LISTEN、记录旧 Codex PID，但 CIM 与原生进程查询均无该进程、HTTP 接口不响应的状态。入口此前固定使用 9335，因此即使已正常退出客户端也会停止启动。

后续对象级检查定位到另一个长期运行的应用及其语言服务仍共同持有原监听套接字。只读诊断通过正常进程继承，在诊断子进程自己的句柄上调用 `getsockname` / `getsockopt`，确认该对象为原端口的监听；没有使用 `DuplicateHandle` 复制 socket，没有关闭外部句柄。用户正常退出持有者后，原端口 LISTEN 消失，独占绑定成功，当前壁纸保持运行。TCP 表记录的是最初绑定的 PID，不能仅凭该 PID 消失就判定为内核残留，也不需要为这次清理重启 Windows。

## 修复

- 优先重新验证保存端点及默认端口。没有可复用连接时，从 9335–9354 选择空闲端口；不关闭占用者，不绑定公网地址。
- 保存的 `cdp-endpoint.json` 与 `runtime-status.json` 只提供端口提示。每次均验证唯一监听 owner、当前 Windows session、官方登记的主程序路径、进程创建身份和实际 CDP 浏览器；损坏记录、其它会话、辅助进程及 PID 变化均拒绝复用。
- CIM 的创建时间只有微秒精度。与原生创建时间作精度容差核对后，记录原生 100ns 时间，避免把同一进程误判为已替换。
- 启动前重查主实例及端口，端口被抢占时重新选择；普通主实例仍存在时不另开第二份。现有协议重定向回退也重查端口，更新事件仍不新增关闭或重试。
- 验证连接后原子保存端点提示；保存失败只记警告，不触发关闭健康客户端。壁纸宿主、任务栏对齐与更新恢复使用同一实际端口。
- 入口互斥/事件名称保持稳定，不因不同端口绕过单入口保护。`npm start` 仍是手动开发诊断用的 9335 默认命令，普通使用通过一体入口。
- 一体入口、自检、更新辅助程序和宿主启动使用原生进程启动：无重定向时不继承句柄，有重定向时只允许明确的标准流句柄。已登记 Store 可执行文件的直接启动同样经过此路径。短命子进程在恢复执行前关联管理句柄，保留退出码。
- 从调试客户端代开其它长期运行的应用时，使用 `windows/Start-ExternalApp.ps1 -FilePath <绝对可执行文件路径>`。它只负责这一次启动，随后退出；不改应用、快捷方式或用户配置，不创建常驻。正常桌面/开始菜单入口仍可使用。
- 官方 Codex 后续创建自己的子进程时，其句柄继承属性由官方实现决定；本项目的启动函数只管理由它实际创建的进程。官方监听 socket 及每条内部 spawn 路径需要各自设置不可继承或显式句柄列表。

## 句柄继承回归

`test/clean-process.ps1` 使用真实隔离 Windows socket 和子进程：旧路径中，父进程退出后，存活子进程保留监听、独占绑定失败；新路径中，子进程同样保持存活，但原端口立即可独占绑定。标准流重定向也经过该检查，另核对 Windows 引号/末尾反斜杠、工作目录、环境及立即退出的退出码。测试只创建自有夹具，不连接或关闭真实客户端。

## 已验证与剩余验收

`test/cdp-endpoint.ps1` 覆盖端口占用、空闲后备、保存端点重新验证、非法/损坏记录、全部占用、会话/主进程/创建身份及精度核对。`test/startup-shutdown.ps1` 执行实际 bootstrap 并隔离包/进程/激活接口，验证 9335 残留时只发一次 9336 调试启动、9336 临时被占时改用 9337，以及普通实例仍运行时不启动。启动策略、健康记录、更新 no-close 回归通过；没有操作真实占用者。

最初一次后备端口恢复中，一次性恢复以退出码 0 完成，启动状态为 `background-rendered`，实际端口为 9336，主/分离页面均 ready；设置与启动前的完整文件哈希一致。当时保留了 9335 的旧监听。保存端点的严格重新验证返回 `verified-client-reused`，宿主决策为 `reuse`。之后按上文定位持有者并由用户正常退出，9335 已释放；持有者从原有桌面入口重新打开后，不再持有 Codex 调试端口。

宿主记录主画面首次 ready 约 1681ms，不包括 Codex 自身启动、身份校验和此前等待用户退出的时间；该次客户端启动/验证阶段约 21 秒，不能把 1.68 秒宣传为完整启动耗时。此为本机当前版本的一次正常进程重开，不是 Windows 开机或 OS 冷盘测试。

后台直接调用启动脚本做完整唤回时，Windows 拒绝授予前台焦点，脚本按原保护报告失败并保留客户端；这是后台验证上下文的限制，不作为真实用户点击的前台唤回验收。端点及宿主复用随后用只读检查通过，运行中壁纸不受影响。私人设置、占用快照和恢复日志保留在仓库外，不修改失败记录来掩盖这项边界。
