# 开源准备审查（2026-10-28）

本次检查覆盖源码、安装/升级/恢复、依赖解析、进程识别、第三方来源、隐私说明、发布清单和 Git 历史。仓库保持私有，安装包保持草稿；未操作当前客户端、用户配置、桌面快捷方式或更新任务。

## 发现并修复

| 问题 | 修正 | 验证 |
| --- | --- | --- |
| 升级后只认识当前源码路径，可能重复启动旧版本仍在运行的壁纸宿主 | 识别当前数据目录下的精确版本化宿主路径；健康且连接同一浏览器时复用，失联/运行时不同/状态缺失时停止重复启动 | 旧版本、失联、Node 路径变化、状态缺失与外部路径策略用例 |
| 连续使用“替换快捷方式”安装时，后备分支可能覆盖已托管快捷方式，使还原哈希不匹配 | 整个替换分支识别已经接入的入口，保留其字节与原始备份索引 | 连续两次完整替换分支后逐字节还原原快捷方式，仅操作临时目录 |
| 名称类似 WindowsApps 的任意目录可能被误认作官方客户端 | 要求当前用户登记的 Store 包家族、固定发布者与可信安装根；无法确认的旧根阻止重复启动，保留其进程 | 伪目录、不同发布者、跨会话、旧根及真实包登记只读核对 |
| 安装器只确认 ffmpeg，漏掉实际导入需要的 ffprobe | 要求同目录两个可执行文件均可运行；显式无效覆盖直接报错 | 合成可执行文件分别覆盖缺失/完整组件，不安装依赖 |
| PATH 前面的旧 Node 可能遮住后面的合格版本 | 枚举全部应用候选并逐项验证版本 | PATH 前置 Node 20、后置 Node 24，确认选中后者 |
| 同一会话并行运行安装器会争用稳定入口/配置侧车 | 安装期间使用命名互斥锁，结束后释放，无后台进程 | 子进程安装器在写入前被拒绝 |
| 隐私文档误把全部缓存/配置都归入桥接数据目录 | 说明官方账户配置及 GPU CacheStorage 所在边界、独立 Web 浏览器配置槽和旧目录保留行为 | 对照实际存储实现与启动策略 |

另外设置 `package.json` 的 `private: true`，防止误用 npm 发布不完整文件；它不改变 GitHub 仓库的可见性。安装器、构建入口和更新恢复使用同一套官方包识别规则。第三方源码保持原哈希。

## 验证范围

- 82 项 Node 单元测试通过。
- 启动策略、健康决策、安装选项、连续安装还原、依赖发现、并发拒绝、更新事件和可选运行时路径回归通过。
- 发布文件清单、第三方源码及已审查图片哈希校验；完整 Git 历史扫描；独立目录安装和原生入口空 PATH 只检查；私有远端 CI 与草稿资产回读属于交付核对，具体结果记入执行记录。
- 上述测试不等于全新 Windows 机器验收，也不证明所有原生壁纸或未来客户端版本均兼容。没有为测试重启当前 Codex。

## 发布判断

修复后适合准备有限范围的 Windows 源码 alpha。自然更新后的完整恢复、新机器首次安装、用户真实任务栏点击、休眠/跨 DPI/高刷新率长时间组合仍缺少完整实机覆盖；这些限制不能写成已全部验证。公网直接下载安装命令应在真实公开 Release 地址可用后补充。仓库和 Release 的公开动作仍由用户决定。
