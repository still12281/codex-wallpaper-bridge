# 执行包 B：媒体准备、取消与事务（2026-10-26）

已实施并部署首批 B1—B3 改进。源码与隔离检查、真实客户端后端往返分别列出；仍未覆盖的代表素材和长期行为保持待办。

## 变化

- 先用同一 FFmpeg 安装目录的 ffprobe 检查真实流、编码/像素格式、大小、尺寸、旋转/SAR、帧率和时长；检查空间及源版本。探测缓存按版本失效，最多32项。工具缺失或坏输入给出实际错误，不自动安装依赖。
- 符合尺寸/帧率和载入容量的普通 PNG/JPEG/WebP、无音轨 H.264/yuv420p MP4 直接复制；有音轨的兼容 MP4 只封装视频流并去音轨。保持原有媒体静音语义，需要缩放/降帧或编码兼容时才转码。GIF 继续按动态媒体处理；不声称其它所有编码已走直通。
- 32/128 MiB 与宿主媒体载入限制一致。转码容量只是估算；风险确认提供“按原规格尝试”或“返回调整规格”。实际输出超限、45秒无进展或15分钟总上限会停止并清理，不采用截短文件，不默认降画质。提前检查不能保证发现素材中段所有损坏。
- 转换结果按源路径/大小/mtime/ctime、MIME、规格和算法版本缓存，最多16项/256 MiB。成功保存后才放入缓存，优先同卷硬链接；没有保留闲置渲染器。清理入口同时清浏览器切换缓存和独立转换缓存，保留已保存副本与外部原件。
- 上传块从384 KiB改为2 MiB；仍校验每次长度和总声明大小。旧库缺指纹项仅在源字节大小相符时再算完整哈希，避免无关大文件读取。
- 输出每次提升到独立最终文件，保存配置失败恢复旧元数据及字节，并清新最终文件；配置保存是提交点，之后旧文件清理失败不再回退已保存状态。`customDisplay.file` 纳入引用保护。
- owner/operationId 限定操作身份；最多32个活动任务和64个有时限取消记录。入队前注册，唯一取消旁路只中止相应任务；已开始保存则拒绝取消。防止取消后的排队请求/确认重新创建活任务。
- 哈希、探测、复制和转换检查取消；ffmpeg停止关闭后清输出。上传异常、取消或页面断连清会话；容量/实时确认拒绝也释放任务槽。本地文件输入在结束后复位，允许重新选同一文件。
- 进度来自实际准备阶段和 ffmpeg `-progress`；百分比仅为当前转换阶段。转换并发仍为1；纯文件准备期间允许已有原生帧/频谱通道推进，最终设置/采用/保存继续串行。
- 批次不再把取消计成成功；保留成功项、失败及未开始勾选。当剩余勾选全为失败项，同一个批量按钮显示“仅重试失败的 N 项”。未新增重复批量入口。

实现依据：[ffprobe 官方文档](https://ffmpeg.org/ffprobe.html) 与 [FFmpeg streamcopy/progress](https://ffmpeg.org/ffmpeg.html)。没有新增编码框架或常驻监控。

## 保留边界与后续

- 长视频/真实大素材的阶段计时、真实容量触顶、硬件编码收益与新磁盘空间不足仍未逐项验收；没有据此启用硬编或承诺所有导入更快。Scene/Web继续只保存引用，不混入媒体转码指标。
- 图片真实客户端仅保存/取消已验收；视频快路径实际解码在隔离端到端验证。真实 Codex 中长导入同时维持原生采集/音频的动态效果、批次取消与仅重试失败仍需相应样本，不能由消息/接口存在冒充。
- 实际损坏输入仍可能失败，硬件/编码覆盖不是零失败保证。进程被系统强杀后的断电恢复及旧历史孤儿文件扫描未在本阶段自动执行，避免顺带清用户旧文件。
- 旧宿主退出原因无日志证据，恢复连接只解决当前失联状态，未宣称根因已查明或永不复发。A1具体浮层/额度卡片视觉、C—E功能与系统验收仍独立保留。
