# 启动等待优化与验证边界

用户已确认退出恢复后壁纸可见；真实运行状态的主/分离窗口均 ready。此前启动器在 45 秒检查截止时报首帧未就绪，后来宿主继续加载成功。原记录没有细分耗时，不能把全部真实延迟归因于单一调用。

## 已修正的等待链

- 按主窗口、分离窗口排序；每个窗口真正 ready（或明确禁用）即发布状态，启动器不必等待其它窗口全部结束。
- 附属网页同步改为独立的单次在途任务，不占主窗口装配及操作队列；关键等待后复核当前设置，旧主题/开关请求恢复后会立即采用最新配置。
- 任务栏身份对齐在画面就绪后异步执行，合并重叠请求。
- 初始界面未就绪时，沿用同一个轮询计时器按 250ms 检查；就绪后恢复 5 秒间隔。
- 素材缓存读取使用页面内 250ms–2s 的有限预算（按资源大小）。缓存初始化、同键写入、查询或读取过慢时，走已有原文件读取/传输后备。缓存是可选优化，不再成为已读取素材交付的前置条件。
- 缓存操作到期后失效，取消流读取，迟到结果不能再次交付；缓存 Response 仍在转移资源 buffer 前构造。原文件版本、范围、尺寸、取消检查及缓存容量上限保留。
- 宿主记录 `startup`、每窗口 `mountMs`；入口记录最多 24 个 `phaseHistory` 条目，用于下一次冷启动分段诊断。

渲染引擎、画质、分辨率、FPS、脚本、音频功能和官方 CSP 均未因这次优化降低或放宽。
