# 实时场景与网页模式

本机已对一张已安装场景执行真实 WGC 采集和 Codex canvas 播放、规格切换及恢复原背景检查。采集端 960/12 约 12FPS；Codex 输出在 1280/24 设置下约 18FPS，在 960/12 下约 10FPS。这里的 FPS 是输出上限，尚不保证达到设置值；没有全 GPU/CPU 占用或所有壁纸兼容性结论。

2026-10-24 补充：自制网页动画通过真实原生采集，约 1.6 秒收到 21 帧且画面哈希变化，停止后源载体已关闭。这不代表所有工坊网页兼容。

## 工作方式与准备

Wallpaper Engine 在独立窗口运行场景/网页；Windows.Graphics.Capture 只采集这个带随机唯一名称的窗口。画面通过有界 JPEG 帧传到 Node，再经本机 CDP 绘制到背景 canvas。不采集整个桌面，不保存连续帧，不上传画面，只保留最新帧。

专用窗口首次创建时即使用屏幕外坐标，采集助手设置 TOOLWINDOW/NOACTIVATE 并保持非最小化。它仍是后台渲染载体，但不需要用户保留一个可见源窗口。SW_HIDE、最小化、全屏暂停策略及不同 GPU 环境的行为不作为已支持能力。暂不转发鼠标交互。

安装 uv 与 Python 3.12 x64，然后运行 `./windows/Prepare-Realtime.ps1`。准备过程从 PyPI 下载锁定依赖到运行数据目录的 capture-cache；应用时使用离线环境。可配置 CODEX_WALLPAPER_UV、CODEX_WALLPAPER_PYTHON（准备脚本）及 CODEX_WALLPAPER_ENGINE_EXE。源码不随附这些程序或第三方二进制。

## 导入和规格

搜索场景，选择“原生实时 · 场景 / 网页”，然后导入并应用或仅保存。自动模式优先尝试视频层，无法提取时询问实时模式。

两种导入都必须二次确认。取消时不保存记录、不启动渲染、不切换背景。仅保存只记录项目引用，之后从“我的壁纸”应用时再次确认。首帧/启动失败恢复原选择；运行中采集异常尝试恢复最近的图片/视频背景，没有回退项则停止背景并报错。

最大宽度控制专用渲染窗口尺寸，沿用现有 1280:900 包围框；帧率上限控制 JPEG 采集输出。JPEG 品质固定 78，不控制源项目贴图或抗锯齿。源端全局 FPS/特效仍由 Wallpaper Engine 管理，不静默改动桌面全局设置。后台暂停只暂停采集输出/绘制，源引擎仍可能渲染。

## 手动验证

1. **取消**：强制完整实时，点导入并应用。确认框应显示项目、规格和持续运行说明。取消后背景、库数量不变，不新增专用窗口。
2. **仅保存**：确认仅保存后出现“· 实时”记录，背景不变、无新渲染窗口。之后选择该记录应再次确认。
3. **应用**：确认后后台载体运行，Codex 显示完整场景效果，桌面壁纸保持原样。前台不应出现源窗口、标题栏、聊天或整个桌面内容。
4. **遮挡**：Codex 完全挡住专用窗口时，观察动态是否继续。不要最小化源窗口；全屏停帧时检查 Wallpaper Engine 的暂停规则。
5. **规格**：1280/24 改为 960/12，点应用播放规格，应关闭旧窗口、打开新规格窗口并恢复画面，再改回。源端30FPS时采集60不会产生60FPS独立画面。
6. **暂停**：切后台再回来，检查采集恢复；这不保证源引擎的 GPU 占用归零。
7. **故障**：维护者定向关闭带随机名称的源窗口，应提示并恢复之前的图片/视频背景；这项已在本机执行并通过。不要为故障测试关闭整个桌面 Wallpaper Engine。导入不存在或无权限项目应提示，不留下新记录。
8. **清理**：换回图片/视频、删除实时记录、正常退出 Codex 后，后台载体和本项目 Python 进程应退出，桌面 Wallpaper Engine 保持运行。换回媒体和定向源关闭后的清理已在本机检查；完整客户端退出仍需单独区分。
9. **持久化**：重开壁纸入口检查记录和规格保留；之前已应用的实时记录会自动重新启动采集。

反馈失败步骤、错误提示和是否出现专用窗口即可；不要公开完整运行数据、个人配置或聊天截图。
