每包开始只读核对：当前任务授权、Git 差异、上次交付记录、实际配置和直接依赖。确认当前用户自己的未提交改动后保留；不得复原历史选择或删除新导入项。

每包结束记录：完成的任务编号、修改理由、定向验证、真实客户端状态、未知/未完成项、提交哈希与下一步。必要时备份部署文件和配置到仓库外。仅暂存本阶段明确文件，重要阶段本地提交；不自动推送或发布。

精简测试：UI 只查代表布局与关键交互；导入只覆盖快速路径/容量/取消/失败恢复；GPU 只查受影响的资源/首帧/音频/输入/生命周期；系统验收集中执行一次。已有测试通过后，仅在相关代码变化、失败或新矛盾时重跑。不新增镜像实现或无意义排列组合测试。

只有会执行文件、脚本、系统窗口或播放行为的改动才需要相应真实验证；文档计划只检查覆盖、链接、差异和发布清单。运行时文件部署与源码检查分开报告，未部署不说已生效。

总体完成条件：T01—T14 无静默遗漏；核心功能有实现和实际证据；外部/用户配合项目有明确状态；可选未实施项有保留记录。存在未实现/未验收项时不能宣布全部完成。

## 新对话执行建议与启动文本

建议新建一个项目内对话开始 A；后续在自然阶段边界按 B/C/D/E 换对话。无需为了拆包强制一次建五个，不同时开多个对话修改同一部署。当前聊天保留总计划。

理由：UI、导入、多种渲染通道和系统生命周期的上下文不同；分包能限制范围并保持阶段回退。新对话不是修复能力前提，也不保证改变账户共享额度；是否新建由用户决定，本轮不自动创建。

用户决定开始实施时，可在新对话发送以下文字（这段仅为模板，本文本身不授权执行）：

> 在现有壁纸项目执行 `docs/EXECUTION-PLAN-20261026.zh-CN.md` 的执行包 A（T01—T04）。先读该计划、task_plan.md 当前入口及 Git 状态，只按需读取历史证据；保留既有功能、源素材和我的当前配置。先完成界面适配与重复操作整理，再统一 UI。减少不重要测试，重要阶段提交本地 Git，不推送；不强关/重启 Codex、不操作桌面、不新增常驻监控。完成 A 后报告覆盖项、验证、未知项、哈希及 B 的接续位置；不要未经本轮授权扩大到其他包。

若用户直接授权连续执行全计划，可按 A—E 继续；阶段交接不自动撤销已有执行授权，但新会话仍以当时的用户请求为准。
