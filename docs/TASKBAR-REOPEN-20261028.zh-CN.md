# 未完全退出时的任务栏唤回

用户反馈：Codex未完全退出时，点任务栏图标无法打开。当前固定项确实指向一体入口，官方图标引用正确；原记录虽写`existingMainWindowReopened=true`，实际仅确认CDP `Page.bringToFront`成功。当前Electron的`Browser.getWindowForTarget`返回`Browser window not found`，旧链路没有核对原生可见性、最小化或前台，不能把原状态当作真实唤回证明。

## 修改

- 已验证主页面仍存在时，直接获取该主页面的外部几何数据；不再每次先调用包激活。主页面不存在时才请求官方包激活重建，随后继续核对同一根进程/浏览器身份，不创建第二客户端根。
- Windows帮助器只匹配已验证官方根进程下、无owner的`Chrome_WidgetWin_1`窗口，依据主页面几何位置匹配；匹配不唯一就停止，分离页/隐藏avatar不作主页面替身。
- 记录同一进程开始时间、主target和窗口句柄的本地提示。后续同一主页面最小化/隐藏时可精确恢复；进程或target变化即弃用提示。提示仅在数据目录，不加入Git。新启动可只记句柄，不改变前台。
- 用户明确点击入口时，只正常显示/恢复该窗口并请求前台；保留最大化状态，不关闭、杀死或重启客户端。入口向本次bootstrap传递前台许可；不绕过Windows焦点限制，失败会如实报告。
- 只有读回“可见、未最小化、处于前台”才标记唤回完成。没有常驻窗口观察器。

## 当前证据

主页面几何只读结果为1309×900，与一个实际原生窗口唯一匹配；avatar为356×320、分离页为960×720，没有误选。只读帮助器成功匹配当前主窗口；后续RememberOnly保存提示，没有改变前台。几何/缩放候选与错误owner拒绝测试通过，实际native entry空PATH检查通过，启动身份/更新后不再关闭客户端的策略检查通过。

已部署修正后的入口及活跃bootstrap源码，当前Codex根进程和浏览器未变化。没有为了测试最小化/隐藏用户窗口。**真实任务栏点击唤回、后台托盘状态和不同DPI/显示器仍需用户正常操作验收**，不能仅凭只读匹配宣称全部修好。匹配或Windows焦点授权失败时保留现场，读取数据目录的`launch-status.json`/`entry-error.log`，不通过强制重启绕过。
