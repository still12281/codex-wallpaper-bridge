# 托盘驻留时的任务栏唤回

## 当前行为（2026-11-06）

Codex 仍在托盘运行时，原任务栏入口复用当前客户端，恢复主窗口、内部页面显示与输入。窗口正常显示后再处理壁纸宿主的补接。

入口先核对主进程路径、完整创建时间、会话、回环监听归属和主窗口 cookie。有效记录走原生入口快路径，调用 Codex 自身的 `open-current-main-window` 显示消息，读回页面可见状态，再核对窗口可见、未最小化与前台状态。消息不携带导航路径，保留当前聊天。

记录中的 HWND 使用窗口属性绑定，cookie 以字符串保存；窗口销毁后原绑定失效。渲染 target 换代时可继续使用同一主窗口，分离窗口和头像窗口不作为替代。真正主页面和 shell 就绪后会刷新记录。记录缺失或失效时走完整核验入口。

壁纸宿主状态过期时，先恢复窗口，再后台请求 attach-only 补接；复用已有可核验的宿主。该请求沿用入口锁，保持客户端与配置。

## 本次错误及修复

旧路径在原生唤醒前读取隐藏 renderer 的几何信息，并将 HWND 提示绑定到启动时的 target ID。target 换代后提示被弃用，随后几何匹配失败，出现 `Cannot uniquely match the verified Codex main page to a native window`。

第一版改为直接显示原生 HWND 后，窗口迅速出现，但用户确认界面无法点击。原生可见状态与内部页面显示状态失配，只有外框检查不足以判定完成。

最终版改用 Codex 自身的主窗口显示消息，恢复内部状态后核对原生窗口。隐藏页面仍未恢复时返回失败并保留客户端。

## 验证结果

- 用户真实操作：关闭窗口回托盘，点击原任务栏入口，立即打开，点击和滚动正常。
- 激活记录：0.874 秒；主进程身份保持，保存设置的完整字节保持。
- 生成检查：同窗口 cookie 复用、64 位字符串往返、错误 owner/cookie、分离窗口、歧义几何、窗口销毁与句柄失效通过。
- 激活模块检查：官方消息正确载荷、几何只读模式、缺失消息入口、恢复后仍隐藏、错误/变化的 browser ID 通过。
- 当前可见窗口的原入口调用约 0.66 秒；这是热唤回记录，冷启动使用独立计时。

实现沿用统一入口和官方图标。窗口恢复不重建客户端；跨 DPI 的任务栏分组检查未执行。
