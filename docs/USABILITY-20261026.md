# 4K、DSH 路线和窗口闪烁：2026-10-26

本轮续接额度中断后的未提交修改。证据来自同一个运行中的 Codex；没有强关或重启客户端，没有改桌面 Wallpaper Engine 的全局画质或当前桌面项目。

## 实际输出与成本

同一场景的有界短采样，均非物理显示帧率，也不是长期稳定性结论：

| 路线 | 实际输出 | 更新率 | 口径 |
| --- | --- | --- | --- |
| 原版兼容，均衡 | 1280×900 | 24.12/s | Codex canvas 更新数/时间 |
| 原版兼容，4K | 3840×2160 | 11.09/s | Codex canvas 更新数/时间；采集上限 30，JPEG 92 |
| DSH GPU，4K | 3840×2160 | 约 30 FPS | WebWallGL renderer stats；上限 30 |

DSH 路线复用了 MIT 的 v1.4.0 renderer.js（commit `3b0103bc1d5431840208966ce67155f392c4095c`），在既有 opaque iframe 中运行控制源码，保留项目能力资源围栏、首帧检查与失败保留旧背景。它与原有 GPU 路线使用同一个 WebWallGL 3.0.0；这不是整套 DSH 插件移植，也没有移植其 HTTP 服务。资源仍仅在加载时通过 CDP 分块传输，连续画面由 GPU 直接渲染，避免原生逐帧 JPEG 编码、转发和解码。不能把这份复用本身说成更强的场景兼容性。

系统媒体采集更新固定 64 段 Float32Array，渲染帧复用同一缓存；无真实输入时返回零频谱。真实 Codex 中已观察到持续 spectrumUpdates 和系统音频桥活跃；暂停后 renderer running=false、FPS=0、频谱关闭。没有以模拟波形冒充系统音频。第三方字体、脚本和效果仍可能与原版不同。

当前素材视频为 3840×2650，4K GPU 纹理上传保持 100%。当前显示器报告 1920×1080，Codex 内容视口 1309×900，DPR=1；1280 宽已接近窗口实际像素宽度。3840×2160 要缩小到窗口，且有遮罩，所以细节差异不会等于在 4K 显示器上逐像素观看。档位名称与实际输出分开显示，不能仅凭标签认定画质已提升。

## 后台占用口径

原生 4K 短采样：桥接约 104 MiB、采集助手合计约 162 MiB working set，CPU 分别约整机 3.41%/5.04%；共享的 Codex/桌面引擎仍有额外成本。DSH GPU 不需要原生采集助手，也不创建额外的原生壁纸窗口。

清理已传完的大资源缓冲后，DSH GPU 播放采样桥接约 51 MiB、媒体约 24 MiB。后台暂停的 4 秒采样约 39+22 MiB，CPU 合计约整机 0.10%；场景 rendering=false/FPS=0，频谱停止。加载结束的大块宿主资源缓冲已从约 212 MB 降到不足 2 MB。working set 会随系统回收变化；private commit 不是物理 RAM。

Codex 共享进程的内存、CPU 和 GPU 显存不能准确拆成壁纸独占量。这些助手数据不是全部壁纸内存；共享进程总量也不能冒充壁纸增量。未做严格空闲机器实验或长期显存泄漏验收。

## 闪烁与窗口

失焦 1.5 秒即销毁源窗口的未提交逻辑，会在重新聚焦时重建原生窗口；旧日志显示打开到完成屏外隔离约有 1.3 秒空档，与用户观察到的闪出壁纸高度吻合。已删除这条焦点销毁/重建路径，保留采集暂停和最后画面；原生引擎后台仍可能渲染，这是兼容路线的资源取舍。

采集解释器现在先进入等待态，再请求原生窗口；按唯一名称尽早设置 NOACTIVATE/TOOLWINDOW、移到屏外，并检查 SetWindowPos 与窗口矩形。实际暂停、恢复和任务栏入口调用后保持同一个 HWND；官方 Codex PID、启动时间和 browser identity 保持不变。最近入口唤回约 1.25 秒。DSH 路线没有额外原生窗口，因而避开此类源窗口暴露。

隐藏页面的 GPU 初次装载延后至页面可见，避免隐藏状态下没有 rAF 首帧却被判为坏场景。正常页面重载仍可恢复绑定。

控制页保留在 Codex 内：标题栏拖动、四边四角缩放、双击/按钮最大化与还原、窗口尺寸记忆、内部内容滚动。真实指针测试修复了重组时标题元素脱离 ShadowRoot 查询范围的问题。冗长说明收进帮助；删除隐藏省电按钮、场景视频层提取以及废弃 supervisor 源码和旧测试，保留现有用户视频记录。

## 验证和剩余边界

22 项相关单测、隔离 GPU 生命周期/频谱/失败保留、控制面板实际指针和布局、媒体导入应用流程、入口空 PATH 和进程身份策略检查通过。实际 Codex 已运行两种 4K 路线；保存的外观、音频、失焦暂停、预设与轮播偏好保留。

仍需用户正常关闭主窗口后的完整唤回观察、真正冷启动、睡眠唤醒以及首次创建原生窗是否仍偶发闪烁。窗口重用证据只证明已去除反复重建，不证明所有系统级闪屏原因都已消除。原生鼠标交互、所有场景兼容性、物理呈现延迟和长期 GPU 显存仍未验收。
